# Captain 0.1.0-alpha.15

Captain's fifteenth public early-access release separates the complete Agent
OS from two lightweight components: a multi-Captain Console and an optional
outbound execution Node. One Captain Full remains authoritative for each
session, project, memory, approval, and run. The lightweight components never
create a second agent loop or silently merge independent Captains.

## Install Captain Full

macOS, Linux, and VPS:

```bash
curl -fsSL https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.15/install.sh \
  | CAPTAIN_VERSION=v0.1.0-alpha.15 bash
```

Docker (`linux/amd64` and `linux/arm64`):

```bash
docker pull ghcr.io/vivien83/captain-agent-os:v0.1.0-alpha.15
```

The moving prerelease channel is
`ghcr.io/vivien83/captain-agent-os:alpha`. Pin the immutable version tag for a
reproducible deployment.

## Install Captain Console

Console is a standalone lightweight binary. It contains no provider, agent
loop, memory database, MemPalace runtime, channel bridge, Python environment,
or local Full daemon.

macOS or Linux:

```bash
curl -fsSL https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.15/install-edition.sh \
  | CAPTAIN_EDITION=console CAPTAIN_VERSION=v0.1.0-alpha.15 bash

captain-console pair --hub https://your-captain.example
captain-console tui
```

Windows PowerShell:

```powershell
$env:CAPTAIN_EDITION = "console"
$env:CAPTAIN_VERSION = "v0.1.0-alpha.15"
irm https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.15/install-edition.ps1 | iex
```

`captain-console list`, `use`, and `rename` manage local labels and explicit
authority selection. `open` renders the selected Hub through a private
loopback gateway, while `tui` restores and streams the same Hub sessions in a
small Ratatui client. Neither surface exposes the Hub bearer to JavaScript,
logs, or terminal projections.

## Install Captain Node

Node is optional. Install it only on a machine where Captain must access a
local workspace:

```bash
curl -fsSL https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.15/install-edition.sh \
  | CAPTAIN_EDITION=node CAPTAIN_VERSION=v0.1.0-alpha.15 bash

captain-node pair \
  --hub https://your-captain.example \
  --workspace "$PWD"
captain-node service install
```

Pairing is read-only by default. `--allow-mutation` requests a separate grant
that the Hub must approve. `captain-node service install/start/stop/status/
uninstall` uses launchd, systemd user services, or Windows Service Control
Manager. The same cooperative shutdown path is used by foreground Ctrl+C,
SIGTERM, and the Windows service manager.

## Multi-Captain authority

- Console stores several local profiles without joining their data. A profile
  has one exact Hub instance UUID and HTTPS origin; a credential can never be
  reused automatically for another destination.
- Selecting another Captain is explicit. A failed bootstrap leaves the current
  authority unchanged, and an offline profile never falls back to a local Full
  runtime.
- Profile probes run concurrently but remain bounded by concurrency, timeout,
  body size, and output fields. Inventory keeps only sanitized version, model,
  health, alerts, session/project counts, and official quota windows.
- Long-lived Client credentials live in macOS Keychain, Windows Credential
  Manager, or the supported Linux secret service. Local JSON contains only a
  reference. Legacy single-profile state migrates atomically and fails closed
  on ambiguity or secret conflict.
- The native Desktop wrapper uses the same Console manager. Its tray can switch
  among configured Captains, but the Hub-rendered WebView cannot enumerate or
  select another local profile through JavaScript. Alpha 15 does not publish a
  separately signed/notarized Tauri application bundle; the supported public
  lightweight artifact is `captain-console`.

## Outbound local execution

- `captain-node` opens only outbound HTTPS 443. WebSocket is preferred;
  streaming HTTP and bounded long polling provide deterministic proxy
  fallbacks. Explicit/environment proxies, `NO_PROXY`, authenticated proxy
  secrets, and enterprise CA bundles are supported.
- Physical paths stay on the Node. The Hub uses a logical workspace identifier,
  and the Node reapplies workspace, traversal, tool-family, mutation, approval,
  timeout, output, and guarded-shell policies before every call.
- The local tool engine is the standalone `captain-node-tools` crate. Node does
  not depend on the Captain kernel, runtime, providers, memory, skills,
  channels, Wasmtime, ORT, or Python.
- Sequences, acknowledgements, leases, heartbeats, idempotency keys, terminal
  evidence, and the local outbox survive restart. A possible unacknowledged
  effect becomes `uncertain`; Captain never replays it blindly.
- Hub acknowledgement times are clamped to the persisted outbox creation time
  and its cursor never moves backward, so a wall-clock rollback cannot violate
  the durable delivery transaction.
- Node status is read-only and does not create Full state. Reset requires an
  explicit confirmation and refuses while the worker owns the runtime lock.

## Shared sessions and private gateway

The lightweight TUI lists, creates, restores, and streams sessions owned by
the selected Full authority. Session selection is detached from the Hub's
global active-session pointer, so two Clients can restore the same conversation
without changing another surface. Tool phases remain visible, while raw input,
raw output, origins, credentials, and local paths stay outside the projection.

The Console Web path uses one immutable loopback gateway per selected profile.
Requests require its private local session cookie and exact loopback origin;
foreign origins, cross-site fetch metadata, alternate hostnames, unexpected
schemes, and userinfo URLs are rejected.

## Certification boundary

The Alpha 15 system smoke proves:

- a fresh Console and read-only Node status create no Full agent, memory,
  channel, Python, or Full configuration state;
- two independent Full authorities reject crossed credentials and revocation
  takes effect on the next request;
- two Client credentials restore the same durable Hub session;
- WebSocket refusal falls back to bounded HTTPS and later resumes without
  replacing the durable Client identity;
- a granted file read and mutation stay inside one workspace, traversal is
  rejected and redacted, and a crash after effect but before acknowledgement
  does not duplicate execution;
- a deterministic backward-clock acknowledgement preserves the outbox
  constraint and completes the same Hub/Node handshake;
- the durable no-clobber filesystem primitive compiles on every published
  Unix target with its explicit platform dependency;
- launchd/systemd definitions preserve cooperative stop and restart policy,
  and the real Windows Service entry point compiles for its target;
- Console and Node dependency trees exclude every forbidden Full subsystem.

These deterministic loopback and platform-contract tests certify the software
composition. Each real Hub domain, proxy, enterprise CA, firewall, and Node
workspace still requires deployment-specific verification.

## Release supply chain

The release contract contains exactly 54 host assets: 15 archives (Full,
Console, and Node across five targets), 15 SHA-256 sidecars, 15
component/platform manifests, six installers, one aggregate manifest, one
deterministic in-toto/SLSA v1 provenance statement, and its SHA-256 sidecar.
All host targets and both Docker architectures are built locally and strictly
one at a time.

Every lightweight installer verifies the adjacent SHA-256, rejects unsafe
archive paths, probes the exact installed component/version, and restores the
previous binary after a failed probe. macOS binaries are ad-hoc signed but not
Apple-notarized; Windows binaries are not Authenticode-signed.

The final dependency gate incorporates the 2026-08-17 RustSec advisory for
unbounded empty HTTP/2 DATA frames. The resolved `h2` crate is `0.4.16`, not
the affected `0.4.13` release.

The same release gate cross-compiles `captain-types` on Linux and verifies its
durable `renameat2(RENAME_NOREPLACE)` path with an explicit Linux `libc`
dependency and a direct kernel syscall, rather than relying on the macOS host
configuration or a newer glibc symbol.

## Deferred scope

Alpha 15 does not add a mobile application, application-data connectors,
multi-primary memory synchronization, or a Telegram machine tunnel. Connector
hosting and modern MCP/OAuth integration remain the prepared Alpha 16 scope.
Dropping a connector file never grants or executes it automatically.

## Alpha notice

This is a prerelease. Keep backups and review every Client authority, Node
workspace, mutation grant, capability, automation, external account, and
destructive approval. A stolen device credential remains usable until
revocation. Native host execution is not an OS sandbox.

Captain binds to loopback by default. Remote access requires Captain
authentication and HTTPS; never expose an unauthenticated daemon directly to
the Internet.
