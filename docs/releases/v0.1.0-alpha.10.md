# Captain 0.1.0-alpha.10

Captain's tenth public early-access candidate focuses on production hardening,
durable operations, and one coherent operator experience. It retains Captain
Forge, durable workflow learning, native release monitoring, and Telegram Rich
Messages while closing the security and reliability gaps identified by the
full external audit.

## Install

macOS, Linux, and VPS:

```bash
curl -fsSL https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.10/install.sh \
  | CAPTAIN_VERSION=v0.1.0-alpha.10 bash
```

Docker (`linux/amd64` and `linux/arm64`):

```bash
docker pull ghcr.io/vivien83/captain-agent-os:v0.1.0-alpha.10
```

The moving prerelease channel is
`ghcr.io/vivien83/captain-agent-os:alpha`. Pin the immutable version tag for a
reproducible install.

The release contract contains exactly 22 host assets:

- five platform archives;
- five SHA-256 sidecars;
- five platform manifests;
- four installers;
- one aggregate `manifest.json`;
- one deterministic `provenance.intoto.jsonl` statement;
- one SHA-256 sidecar for that provenance statement.

The five targets are Apple Silicon macOS, Intel macOS, ARM64 Linux, AMD64
Linux, and the AMD64 Windows CLI.

## Security perimeter

- API authentication is deny-by-default when credentials are configured.
  Operational state, provider OAuth, A2A, Config, Terminal, sessions, agents,
  approvals, logs, models, and budgets are private. Only reviewed boot assets,
  minimal health/version, browser authentication, and the independently
  authenticated per-agent ingress route bypass global middleware.
- CORS accepts only exact loopback or explicitly declared HTTP(S) origins. A
  separate `Host` allowlist rejects missing, ambiguous, malformed, and
  undeclared hosts before routing.
- Browser sessions use an installation-specific random signing key, Argon2id
  password hashes, credential epochs, bounded login backoff, and path/IP-bound
  one-time realtime tickets. Password rotation invalidates older sessions.
- Security audit history uses a versioned, length-prefixed SHA-256 chain.
  Corruption is never repaired by rewriting history: Captain seals the damaged
  epoch, exposes degraded health, and opens an append-only recovery epoch.

## Guarded host execution

- Every agent-controlled subprocess sink enters the shared `guarded_exec`
  boundary with execution policy, content-bound approvals, environment
  clearing, workspace and timeout bounds, bounded output, and command-free
  audit events.
- Fresh installs use `full` execution with `safe` critical handling. Routine
  host commands remain available, while normalized catastrophic patterns fail
  closed.
- Captain reports the boundary honestly as `host_process`,
  `environment_scrub`, and `os_isolation: false`. This is not an operating
  system sandbox. Docker and WASM remain separate explicit isolation backends.

## Durable operation and continuity

- Final channel replies enter a durable outbound ledger before transport.
  Leases, bounded retries, dead-letter state, receipts, and restart recovery
  prevent a send failure from being reported as success or rerunning the model.
- Detached delegation is durable and dependency-aware. Independent jobs can
  run concurrently, dependent work remains ordered, and uncertain model
  effects are never replayed silently after restart.
- Project completion uses evidence-bound phase contracts and real goal checks.
  Text-only worker claims cannot produce 100% when execution proof is required.
- Explicit per-turn memory write opt-out now reaches the shared core finalizer.
  Normal resumable transcripts and mandatory audit records remain intact while
  the extra semantic interaction fragment is suppressed.
- Session export covers the complete durable catalog without switching the
  active conversation. Compaction progress is typed across terminal, Web,
  Desktop, API, and Telegram; opaque model work remains indeterminate instead
  of inventing a percentage.

## Operator experience

- Global budgets use one synchronized live snapshot. Codex subscription
  windows, remaining percentages, reset times, active-model classification,
  and monthly spend controls come from provider-reported signals.
- Reasoning is a durable per-agent setting. Auto preserves the provider
  default, explicit None remains distinct, and Codex Ultra maps to the
  provider-supported maximum effort plus bounded root-agent delegation.
- First-use questions provide clickable bounded choices while preserving free
  text. Telegram synchronizes its native slash-command menu and renders normal
  replies, tool activity, learning, usage, approvals, updates, and compaction
  as Rich Messages.
- Ratatui, the Web terminal, Control Web, and its Desktop wrapper share
  bounded rendering, durable session reopening, model identity, quota, and
  operational status contracts.
- Credentials can be mapped to authoritative read-only mounted files. Missing
  external sources fail closed and never revive stale local values.

## Skills and dependency posture

- Remote skill marketplaces are frozen and absent from active API and TUI
  surfaces. Local skill installation requires an existing reviewed directory.
  Prompt-text scanning is labelled `advisory_heuristic`, not publisher-backed
  proof.
- The unmaintained `bincode` 1.x cache format and vulnerable RSA dependency
  branches are removed. SSH accepts Ed25519 and ECDSA P-256 keys.
- Release gates execute the configured and unfiltered RustSec views, pin every
  reviewed exception to its exact package, parent, advisory, and reachable
  surface, and reject unreviewed drift.

## Release provenance

This document describes a release candidate. Public source commit, annotated
tag object, GitHub publication timestamp, GitHub asset digests, OCI index
digest, architecture manifest digests, moving-channel parity, and anonymous
installation evidence are intentionally **unset until the live release has
been published and verified**. They must be filled from observed public
values; no value from an earlier release may be copied.

Host artifacts are built locally, one target at a time, from the clean public
source commit. Their deterministic in-toto Statement v1 / SLSA provenance v1
binds all 20 base assets to that public commit and tree, the exact
`Cargo.lock`, target triples, toolchain, release profile, and real build
timestamps. The statement is checksum-bound but not independently signed, so
this alpha claims no SLSA certification level.

Docker `linux/amd64` and `linux/arm64` are also built and remotely inspected
strictly one after the other with BuildKit provenance before the
multi-platform index is assembled. No automatic paid GitHub Actions workflow
is used.

## Recovery boundary

The durability guarantee begins after the relevant tool or API reports success.
An external side effect still in flight at abrupt termination may require
inspection or an explicit idempotent retry. Backups remain necessary; no local
durability mechanism makes the host disk itself redundant.

## Alpha notice

This is a prerelease. Keep backups and review every installed CapSpec, Skill,
Automation, capability grant, and destructive approval. Native host processes
do not have OS-level isolation, skill prompt scanning is heuristic, and the
host provenance statement is not independently signed. macOS binaries are
ad-hoc signed but not Apple-notarized; the Windows CLI is not
Authenticode-signed. Verify the published SHA-256 sidecar and expect explicit
operating-system approval on first launch.

Captain binds to loopback by default. For remote access, configure
authentication and place Captain behind HTTPS; never expose an unauthenticated
daemon directly to the Internet.

The presentation site is deployed separately at `https://captainagent.fr/`.
Its source is intentionally not part of the public Git repository or release.
