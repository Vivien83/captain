# Captain 0.1.0-alpha.12

Captain's twelfth public early-access release makes long-running work easier to
operate and recover. It adds durable Live Runs, evidence-grounded Web research,
immutable user artifacts, managed VPS domains, and continuous deployment
readiness while preserving Captain's six-hub product shape.

## Install

macOS, Linux, and VPS:

```bash
curl -fsSL https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.12/install.sh \
  | CAPTAIN_VERSION=v0.1.0-alpha.12 bash
```

Docker (`linux/amd64` and `linux/arm64`):

```bash
docker pull ghcr.io/vivien83/captain-agent-os:v0.1.0-alpha.12
```

The moving prerelease channel is
`ghcr.io/vivien83/captain-agent-os:alpha`. Pin the immutable version tag for a
reproducible install.

The release contract contains exactly 22 host assets:

- five platform archives;
- five SHA-256 sidecars;
- five platform manifests;
- four installers;
- one aggregate `manifest.json`;
- one deterministic `provenance.intoto.jsonl` statement;
- one SHA-256 sidecar for that provenance statement.

The five targets are Apple Silicon macOS, Intel macOS, ARM64 Linux, AMD64
Linux, and the AMD64 Windows CLI.

## Durable Live Runs

- Every foreground and detached tool call enters one crash-recoverable ledger
  with a stable run ID, input digest, status, retry lineage, and bounded result
  metadata.
- Long stdout, stderr, and progress stay outside the model context in an
  owner-only store with secret redaction, checksum verification, a per-run
  cap, a global quota, and a seven-day retention limit.
- `tool_run_read`, `tool_run_tail`, and `tool_run_search` let Captain revisit
  bounded evidence while work is active or after it finishes. A disconnected
  surface does not stop capture.
- Restart reconciliation marks unfinished work `interrupted` and retains
  sanitized partial evidence. Captain never replays an uncertain external
  side effect automatically.
- Explicit retries require the original input to match its stored SHA-256.
  Interrupted work also requires an exact uncertainty acknowledgement, and a
  durable three-attempt circuit breaker bounds each retry lineage.
- Authenticated `/api/tool-runs` routes expose only selective metadata and a
  tail capped at 200 lines and 32 KiB. They never return raw input, raw result,
  preview, filename, or a managed disk path. Cancellation succeeds only for an
  active run backed by a live abort handle and is hash-chain audited.
- Control Web opens the same private inventory from its top bar. Full Ratatui
  exposes it through `/runs` with stale-response protection and two-step
  cancellation. Standalone chat and the Web terminal remain metadata-only.

## Evidence-grounded Web research

- `web_research_batch` separates discovery snippets from pages that were
  actually retrieved. Independent searches and fetches can run concurrently;
  dependent verification remains ordered.
- A citation-ready source includes its canonical and final URL, HTTP status,
  retrieval time, retained-content SHA-256, bounded preview, and exact Markdown
  citation text.
- `web_citation_audit` refetches cited pages, rejects URLs outside the audited
  set and quotes absent from the retrieved text, measures inline provenance,
  preserves `[unverified]`, and builds the final Sources block.
- The boundary is explicit: Captain verifies retrieval and verbatim evidence
  presence. It does not claim that either proves semantic entailment or factual
  truth without comparing the claim to the evidence.

## Immutable artifacts

- `artifact_publish` promotes a final workspace file into an immutable,
  checksum-bound version. `artifact_list`, `artifact_inspect`, and
  `artifact_deliver` preserve owner and session provenance under kernel
  authority.
- Authenticated operator routes list artifacts and versions, inspect exact
  metadata, preview passive formats, and download bytes only after size and
  SHA-256 verification. Managed paths never enter API responses.
- Text and Markdown are escaped. HTML, raster images, and PDF previews use a
  sandboxed Content Security Policy. SVG and unknown active formats remain
  download-only.
- Control Web provides a `Fichiers produits` drawer with exact version
  selection, sandboxed preview, and verified download. Ratatui exposes a
  metadata-only `/artifacts` overlay. No destructive artifact endpoint or
  silent version pruning is included.

## Managed VPS domains and readiness

After creating the DNS record, a non-interactive managed install can use:

```bash
curl -fsSL https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.12/install.sh \
  | CAPTAIN_VERSION=v0.1.0-alpha.12 \
    CAPTAIN_PROFILE=vps \
    CAPTAIN_DOMAIN=agent.example.com \
    CAPTAIN_YES=1 \
    bash
```

- Captain keeps its API on loopback, validates the public hostname, waits for
  DNS, refuses unrelated listeners on ports 80/443, and installs an idempotent
  Caddy handoff without replacing other managed sites.
- The complete Caddy configuration is validated before activation. File or
  service failures restore the previous configuration and service state.
- Active `ufw` or `firewalld` policies receive HTTP/HTTPS rules. DNS and the
  VPS provider firewall remain explicit operator prerequisites.
- Installation verifies local and public health, TLS, Control loading, and
  exact version parity. The final summary prints the administrator username
  and owner-only credentials-file path without echoing its password or API key
  into logs.
- A daemon worker repeats local/public readiness checks every five minutes.
  `captain doctor --full`, CLI/Ratatui Status, `GET /api/status`, and Control
  read one private crash-safe snapshot with fixed remediation actions.

## Recovery certification

- A process-level power-loss smoke commits memory, project state,
  configuration, one detached canonical session, and an audit checkpoint,
  then sends the daemon a real `SIGKILL`.
- The second boot must reopen and activate that exact session, preserve the
  pre-crash audit tip in the same healthy epoch, recover each acknowledged
  value, and pass SQLite `integrity_check`.
- The same test leaves a Live Run in flight. Restart must classify it
  `interrupted`, finalize only its matching partial capture, redact a synthetic
  secret, preserve bounded private inspection, and refuse terminal
  cancellation or automatic replay.

## Approval-learning boundary

Alpha 12 contains a disabled-by-default core that can recognize repeated
one-time Low or Medium approvals only when agent, tool, and complete action
digest are identical. It stores no raw action and grants no authority by
itself. A candidate would still require explicit operator acceptance to create
an existing exact revocable rule. This release does not claim operator-facing
list, accept, dismiss, Telegram-card, or prompt-shaping behavior for that core.

## Destination and retention boundary

The Live Runs operator API uses only Captain's existing API-key or authenticated
Web-session boundary. Its selective metadata and redacted tail are not sent to
Telegram or a model provider. Artifact preview and download stay in
authenticated Control Web; Ratatui remains metadata-only. External artifact
delivery occurs only when an agent explicitly invokes the existing native
channel-delivery tool under its configured authority.

## Local release chain

Host and Docker release targets are built locally and strictly one at a time
with disk/load checkpoints. The host provenance statement binds all 20 base
assets to the public source revision, Git tree, `Cargo.lock`, target triples,
toolchain, release profile, and real build timestamps. It is checksum-bound but
not independently signed, so Captain claims no SLSA certification level.

Docker `linux/amd64` and `linux/arm64` are also built and remotely inspected
one after the other with BuildKit provenance before the multi-platform index is
assembled. No automatic paid GitHub Actions workflow is required.

## Alpha notice

This is a prerelease. Keep backups and review every installed CapSpec, Skill,
Automation, capability grant, external account, and destructive approval.
Native host processes do not have OS-level isolation, skill prompt scanning is
heuristic, and the host provenance statement is not independently signed.
macOS binaries are ad-hoc signed but not Apple-notarized; the Windows CLI is not
Authenticode-signed. Verify the published SHA-256 sidecar and expect explicit
operating-system approval on first launch.

Captain binds to loopback by default. For remote access, use the managed-domain
installer or configure authenticated HTTPS yourself; never expose an
unauthenticated daemon directly to the Internet.

The presentation site is deployed separately at `https://captainagent.fr/`.
Its source is intentionally not part of the public Git repository or release.
