# Captain 0.1.0-alpha.11

Captain's eleventh public early-access release focuses on secure extensibility,
durable external operations, and practical account integrations. It closes the
remaining Alpha 10 audit gaps, adds native Gmail and multi-account IMAP/SMTP
rails, improves provider visibility, and keeps the complete build and
publication chain local and sequential.

## Install

macOS, Linux, and VPS:

```bash
curl -fsSL https://github.com/Vivien83/captain/releases/download/v0.1.0-alpha.11/install.sh \
  | CAPTAIN_VERSION=v0.1.0-alpha.11 bash
```

Docker (`linux/amd64` and `linux/arm64`):

```bash
docker pull ghcr.io/vivien83/captain-agent-os:v0.1.0-alpha.11
```

The moving prerelease channel is
`ghcr.io/vivien83/captain-agent-os:alpha`. Pin the immutable version tag for a
reproducible install.

The release contract contains exactly 22 host assets:

- five platform archives;
- five SHA-256 sidecars;
- five platform manifests;
- four installers;
- one aggregate `manifest.json`;
- one deterministic `provenance.intoto.jsonl` statement;
- one SHA-256 sidecar for that provenance statement.

The five targets are Apple Silicon macOS, Intel macOS, ARM64 Linux, AMD64
Linux, and the AMD64 Windows CLI.

## Audit closure and execution boundary

- Private API and browser routes fail closed until setup provisions an API key
  or browser credential. Credentialless loopback development requires an
  explicit compatibility flag and an actual loopback client.
- Detached delegation persists root, parent, depth, and one durable tree-wide
  token reservation. Parent identity, depth 10, and a 500000-token lineage cap
  are enforced transactionally across retries and restart recovery.
- Direct-program approvals bind to an injective domain-separated encoding of
  the executable and every raw argument, not their human-readable rendering.
- Login-limit saturation never evicts an active block. A full map of active
  blocks produces a logged global fail-closed backoff; exposed deployments
  still need an upstream edge limiter.
- Control, Config, Web Terminal, and Desktop use embedded same-origin scripts
  under a CSP with no inline or evaluated JavaScript authority. Rendered model
  Markdown is reduced to a passive allowlist.
- `personal_workstation`, `remote_operator`, and `untrusted_execution`
  deployment profiles are explicit and non-bypassable. Agent policy can only
  narrow daemon policy. Docker and WASM remain explicit rails, never an
  automatic route or host fallback.

## Email accounts and automation

- `captain email connect/accounts/status/test/default/disconnect` provides a
  crash-safe multi-account Gmail OAuth lifecycle. Tokens and client material
  remain in the encrypted vault; metadata stays public-safe in SQLite.
- Official builds may embed only Captain's public Google Desktop client ID.
  PKCE, random state, an exact loopback callback, and encrypted refresh tokens
  protect authorization. Development or organization builds can supply their
  own Desktop client JSON without publishing it.
- Native Gmail tools cover bounded search/read, draft-first compose/reply,
  reversible labels and message changes, and workspace-safe attachment saves.
- Deterministic Gmail rules route exact matches to a registered agent through a
  durable delivery queue. Dead work can be retried explicitly; an uncertain
  outcome requires session inspection and duplicate-risk consent.
- The conversational Email channel now supports named IMAP/SMTP accounts,
  per-account allowlists and agent routing, independent adapters, and one
  explicit default. Guided CLI and schema-driven TUI/Desktop/Web forms preserve
  existing accounts and keep passwords outside TOML.
- IMAP acceptance is crash-safe: UIDVALIDITY, UID, mailbox, and folder form the
  durable identity. Captain persists acceptance before marking a message seen,
  re-acknowledges a retry without a second model turn, and does not merge
  sessions across mailboxes.

## Provider and operator awareness

- xAI is available as a first-use provider with non-billable credential and
  ACL validation. API keys are the native path. Captain recognizes an
  externally issued OAuth bearer, but does not invent a login or refresh flow
  that xAI has not published for third-party clients.
- Provider-confirmed subscription resets enter a durable outbox and produce one
  Telegram Rich card. Captain requires both an advanced reset identity and
  replenished provider-reported capacity; it never estimates entitlement from
  a local timer.
- Channel readiness is one live API contract shared by CLI, TUI, Desktop, and
  Web Terminal. Partial, locked, invalid, disabled, and ready states remain
  distinct. Failed loads terminate visibly, secrets stay masked, and HTTP 200
  error envelopes are not reported as successful tests.
- The encrypted vault master key uses macOS Keychain, Windows Credential
  Manager, or Linux Secret Service/keyutils. Headless systems use the explicit
  `CAPTAIN_VAULT_KEY` authority; legacy migration is verified before deletion.
- The Email parser chain moves to the exactly pinned `imap 3.0.0-alpha.15` and
  `imap-proto 0.16.7`, removing the future-incompatible parser macros and the
  obsolete `lexical-core` dependency.

## Local CI and public discovery

- A trusted local PR portal evaluates the exact pull-request SHA inside a
  disposable Lima VM, publishes `captain/local-pr-gate`, and recovers orphaned
  pending states after a host restart. Trusted scripts and toolchains are
  root-owned; submitted source is sealed read-only before network access is
  removed.
- Host and Docker release targets are built locally, one target at a time,
  with capacity checkpoints. No automatic paid GitHub Actions workflow is
  required.
- Repository description, homepage, and factual topics are versioned and
  read-back verifiable. The launch site publishes crawler, canonical, social,
  schema.org, sitemap, and IndexNow metadata. Search-engine indexing remains an
  asynchronous external decision, not a release-gate claim.

## External authorization boundary

No release artifact contains a Google client secret, Gmail refresh token,
mailbox password, xAI credential, or user entitlement table. A real Gmail OAuth
consent or IMAP/SMTP login requires the operator's account and therefore cannot
be simulated by the public source gate. The release gates verify protocol,
storage, migration, crash recovery, request typing, and secret non-disclosure;
the live account check remains an explicit operator action with
`captain email test` or `captain channel test email[:alias]`.

## Recovery boundary

The durability guarantee begins after the relevant tool or API reports success.
An external side effect still in flight at abrupt termination may require
inspection or an explicit idempotent retry. Backups remain necessary; no local
durability mechanism makes the host disk itself redundant.

## Alpha notice

This is a prerelease. Keep backups and review every installed CapSpec, Skill,
Automation, capability grant, external account, and destructive approval.
Native host processes do not have OS-level isolation, skill prompt scanning is
heuristic, and the host provenance statement is not independently signed.
macOS binaries are ad-hoc signed but not Apple-notarized; the Windows CLI is not
Authenticode-signed. Verify the published SHA-256 sidecar and expect explicit
operating-system approval on first launch.

Captain binds to loopback by default. For remote access, configure
authentication and place Captain behind HTTPS; never expose an unauthenticated
daemon directly to the Internet.

The presentation site is deployed separately at `https://captainagent.fr/`.
Its source is intentionally not part of the public Git repository or release.
